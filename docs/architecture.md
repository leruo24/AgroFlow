# AgroFlow architecture: package diagram to code

This maps every package in `docs/diagrams/package-diagram-v2.drawio` to the folders that implement it. The backend folders follow the diagram (October 2026 restructure; `git mv` only, namespaces unchanged). `backend/AgroFlow.Api/Endpoints/` is the HTTP entry point that both front ends call.

| Layer | Package (diagram) | Real folders |
|---|---|---|
| Presentation | Admin Console (+User, +Farm, +Enquiry / Onboarding, +Installation / Kit wizard, +Report, +Settings & Moderation) | `apps/web/admin/src/` (pages/, app/, ui/, features/, services/agroFlowApi.ts). Server side: `backend/AgroFlow.Api/Endpoints/` (EnquiryAdminEndpoints, FarmerOnboardingEndpoints, DeviceEnrollmentEndpoints, ZoneHardwareEndpoints, ReportEndpoints, DroughtCommunityEndpoints, UserEndpoints), `backend/AgroFlow.Api/Auth/`, `backend/AgroFlow.Api/Reports/` |
| Presentation | Farmer App (+FarmUser, +Dashboard, +SetupTasks, +ZoneView, +KitStatus, +AlertsView) | `apps/mobile/src/` (app/ screens, app/(tabs)/ Home / Irrigation / Kit / Alerts / More, components/, lib/, services/agroFlowApi.ts, i18n/). The same code is the farmer web app (Expo web export). Server side: `backend/AgroFlow.Api/Endpoints/` (FarmerEndpoints, TodayEndpoints, KitStatusEndpoints, JourneyEndpoints, TelegramEndpoints) |
| Logic | Sensor Monitoring (+SoilMoistureSensor, +TemperatureSensor, +HumiditySensor, +SensorReading) | `backend/AgroFlow.Api/SensorMonitoring/` (MqttConnectionService, MqttTopics, SensorReadingProcessor, DeviceStatusMonitorService, MoistureFaultService, DeviceAuthService, MqttCredentialPoolService, KitReportColumns, SimulationService), `backend/AgroFlow.Domain/SensorMonitoring/` (Sensor, SensorReadingTypes, ReadingAge, MoistureFaults, KitHealth, ESP32, Hardware, DeviceToken, DeviceSetupCommands, Simulation) |
| Logic | Irrigation Control (+Zone, +IrrigationCommand, +IrrigationLog, +Schedule & RunLimit, +Recommendations (FAO-56), +DroughtManager) | `backend/AgroFlow.Api/IrrigationControl/` (IrrigationCommandNotifyService, Fao56EngineService, DroughtEvaluator, ZoneRunLimit, WeatherCollectionService, WeatherBackfill*), `backend/AgroFlow.Domain/IrrigationControl/` (Zone, IrrigationLog, IrrigationRunRules, CommandState, AutoIrrigationDecision, Pump, TankPh, Fao56EngineController) and `IrrigationControl/Agronomy/` (Fao56Engine, PenmanMonteithEto, DailyEtoResolver, SoilWaterBalance, DroughtManager, RuleBook/) |
| Logic | Notifications (+Alert, +TelegramMessage, +InAppNotice, +CommunityReport) | `backend/AgroFlow.Api/Notifications/` (TelegramNotificationService, TelegramClient, BotText, WeatherAlertService, NotificationLedger, CommunityService, StaffTelegram, Dismissals, TankLowMonitorService), `backend/AgroFlow.Domain/Notifications/` (Alert, CommunityRules, FarmRequestMessages) |
| Data | Data Management (+SyncData, +DataAccess, +ActivityLog) | `backend/AgroFlow.Api/DataManagement/` (AuditLog, AppSettingsStore, JourneyStore, SchemaCheck, SupabaseAdminService, HardwareBacklog, ReportGenerationService, ReportDelivery, AutoReportSchedulerService), `backend/AgroFlow.Domain/DataManagement/` (DB, ZoneDB and the *XDB data-access classes), `supabase/migrations/` (0001–0062), offline sync in the apps: `apps/mobile/src/lib/offlineQueue.ts`, `offlineCache.ts` and on the kit `hardware/esp32/AgroFlowIrrigationNode/OfflineBuffer.h` |
| Hardware | Hardware Layer (+ESP32Node, +Relay, +Pump, +Maintenance) | `hardware/esp32/AgroFlowIrrigationNode/` (firmware 1.7.1: AgroFlowIrrigationNode.ino, RunLimits.h, CommandIds.h, OfflineBuffer.h), `hardware/shared/MQTT_TOPICS.md`, `hardware/sim/` (fake kit and end-to-end tests), `backend/AgroFlow.Domain/Maintenance.cs` |
| External | Supabase (+Auth, +PostgreSQL, +Realtime, +Storage) | `supabase/migrations/`, `apps/mobile/src/lib/supabase.ts`, `apps/web/admin/src/lib/supabase.ts`; the API connects with Npgsql (`backend/AgroFlow.Api/Program.cs`) |
| External | Weather API (Open-Meteo) (+Forecast, +Reference ET₀) | `backend/AgroFlow.Api/IrrigationControl/WeatherCollectionService.cs`, `backend/AgroFlow.Domain/IrrigationControl/Agronomy/OpenMeteoDailyParser.cs`. Open-Meteo gives temperature, humidity, wind and rain; ET₀ is calculated by AgroFlow (`PenmanMonteithEto.cs`, see docs/diagrams/CHECK.md) |
| External | HiveMQ (MQTT broker) (+sensors topic, +commands topic) | `backend/AgroFlow.Api/SensorMonitoring/MqttTopics.cs`, `MqttConnectionService.cs`, `backend/AgroFlow.Api/IrrigationControl/IrrigationCommandNotifyService.cs`, firmware `AgroFlowIrrigationNode.ino`, topics in `hardware/shared/MQTT_TOPICS.md` |
| External | Telegram (+Bot API) | `backend/AgroFlow.Api/Notifications/TelegramClient.cs`, `TelegramPollingService.cs`, `backend/AgroFlow.Api/Endpoints/TelegramWebhookEndpoints.cs` |
| External | Arduino IDE (+Firmware compiler, +ESP32 board package, +USB flash tool) | `hardware/esp32/AgroFlowIrrigationNode/README.md` and `docs/hardware-bringup.md` (esp32 core 3.3.11, ESP32 Dev Module, DHTesp library) |

Files that serve every package stay where they were: `backend/AgroFlow.Api/Services/` (CorsSetup, LegalDocuments, OnboardingAccounts, PasswordResetFlow, StartupConfigurationDiagnostics, EnquiryRateLimiter, TemporaryPasswordGenerator) and the shared domain records in `backend/AgroFlow.Domain/` (User, Admin, FarmUser, Farm, Journey, EnquiryRules, SignInRules, Report*).

The tests are in `backend/AgroFlow.Domain.Tests/` (.NET, with the database tests run by `hardware/sim/run-db-tests.mjs`), `apps/mobile/src/**/__tests__/` (jest), `apps/web/admin/tests/` (Playwright) and `hardware/esp32/tests/` (native firmware checks).
