# Bugs found in the Part 2 test pass

Every bug the Part 2 sweep found: what a person would have seen, why, the
fix, and the test that now stops it coming back. Ten in all; every one was
found by a test written in this pass (or, for bug 1, by reading the request
pipeline while writing one), fixed, and is now guarded.

Fix commits on `test/full-proof`: bugs 1-4 **3e8405b** (part 2 (2)); 5-7
**2df17fc** (part 2 (3)); 8-9 **6ae08c6** (part 2 (5)); 10 **66184d3**
(part 2 (6)).

| # | Symptom | Root cause | Fix | Guarding test |
|---|---|---|---|---|
| 1 | The public "Get a call back" form (landing page and app login, item 6c) answered **401 "Missing or invalid X-Api-Key header"** to everyone, so no enquiry could ever be sent. Its own tests passed because they mocked the API. | The device shared-key gate in `Program.cs` lets through only a fixed list of path prefixes; `/api/public` was not on it. | `/api/public` added to the gate's list. | `ApiContractTests.The_public_enquiry_form_is_reachable_without_a_login_or_device_key` (real pipeline, in memory) |
| 2 | A farm or farmer named `=HYPERLINK("http://…")` (or `@…`, `+…`, `-cmd|…`) became a **live formula** when an admin opened any CSV export in Excel - CSV injection. | `toCSV` quoted values but did not neutralise a leading formula character. | `neutraliseFormula`: such text gets a leading `'`; plain negative numbers like `-12%` and real numbers are untouched. | `hostile.spec.ts` "the activity CSV neutralises formulas…" (fails with the fix removed - checked) |
| 3 | A control character in a name or note (a pasted bell or backspace) made **Excel reject the whole workbook as corrupt**, and made the **PDF fail** on its chart. | XML 1.0 cannot hold most control characters; the workbook and SVG escapers only escaped `& < > " '`. | `ReportText.Clean` drops XML-invalid characters (keeps tab/LF/CR, emoji, accents) in both escapers. | `HostileTextTests` (workbook XML parses; chart SVG parses; PDF renders) |
| 4 | **Any emoji in a farm, zone or admin name made the PDF fail** ("glyph(s) not available in the configured fonts"). Every report carries those names. | QuestPDF's glyph check throws by default when the font has no glyph. | `CheckIfAllTextGlyphsAreAvailable = false` in `Program.cs` and the shared `ReportShell`: the character prints as a blank box, the report is made. | `HostileTextTests.The_pdf_renders_with_the_text_in_it("Tub 🌱 one")` |
| 5 | With the database out of reach, **every API route answered a bare 500 with no body** - the app and console could only say "something went wrong", and the public enquiry form likewise. | No exception handler in the pipeline; the enquiry endpoint did not catch a connection failure either. | A global handler: 503 "AgroFlow cannot reach its database right now…" for database/network failures, 500 with a sentence otherwise, details only in the log. The enquiry endpoint answers its own 503 sentence. | `DependencyFailureTests.Any_route_with_the_database_down_answers_503_with_a_sentence`, `…An_enquiry_while_the_database_is_down…` |
| 6 | An **unreachable MQTT broker only ever showed amber** on the health page ("retrying"), however long it had been gone - the brief requires "down". | Health knew only connected / not connected. | The MQTT service records when the connection was lost; under 2 minutes is amber (a blip the 10 s retry usually recovers), longer is **down** with how long. | `DependencyFailureTests.An_unreachable_broker_is_down_after_two_minutes_a_blip_is_amber`, `…Health_answers_and_names_the_database_and_broker_as_down` |
| 7 | A zone an admin set to **Cucumber or Spinach could not be shown or chosen** on the farmer's Crop screen, and those crops were missing from the enquiry forms. | Item 6b/6c crop lists were copied from the request form (six crops, a database limit on requests only) instead of the console's eight. | One list: the app and the enquiry forms use the console's eight crops, in the same order. | `EdgeCaseTests.Every_crop_list_is_the_same_and_the_engine_knows_every_one` (reads both apps' source) |
| 8 | In the admin console, a refusal from the API - e.g. "Farm size must be greater than 0." when registering a farm - reached the admin as **"Request failed (400)"**; a non-JSON error body surfaced as a **JSON parse error** ("Unexpected token…"); list pages showed the **raw response body**. | Four copies of the error reader read only `detail`/`title` (this API sends `error` or `message`) and rethrew the parse error; `getAuthorized` used the raw text. | One `errorMessage` reader (`error`, `message`, `detail`, `title`, else the text, never raw JSON) used by every helper. | `robustness.spec.ts` "a refused registration shows the server's own sentence…" (fails with the old reader - checked), "…every call failing shows an error with a way out" (no raw JSON on any page) |
| 9 | In the **mobile app**, an API refusal showed as raw JSON on screen (`{"error":"Zone not found."}`). | The request helper threw the raw body. | The same `errorMessage` reader in the app. | `services/__tests__/enquiry.test.ts` "errors from the API" |
| 10 | The app's **Alerts and History showed times in the phone's own time zone and format** - SAST only if the phone was set to it, and an alert at 22:30 UTC could show on the wrong day. | `toLocaleString()` with no zone. | `formatSast` (SAST is UTC+2 all year: fixed arithmetic, no reliance on the phone's zone data) in both screens: "6 Oct 2026, 00:30". | `screens.test.tsx` "lists alerts newest first, in SAST…", "SAST times" (incl. the year-end midnight) |
